# Current Safe Defaults

This page lists the defaults BMF should keep unless a validation task explicitly
requires a higher-risk mode.

## Who Should Read This?

Server operators should use this page when checking production-like installs.
Plugin authors should use it before requesting a capability or unsafe opt-in.
Maintainers should update it whenever a new config gate or environment gate is
added.

## Framework Config

Default `Mods/BMF/config.json` values:

| Setting | Safe value | Notes |
| --- | --- | --- |
| `allowPluginServerExec` | `false` | Keeps `BMF.server.exec` unavailable to plugins unless deliberately enabled. |
| `allowPluginServerShutdown` | `false` | Keeps shutdown automation unavailable to plugins unless deliberately enabled. |
| `jsonlLogs` | `true` | Keeps durable `events.jsonl` and audit evidence available. |
| `pluginWatchdogEnabled` | `true` | Isolates repeatedly failing plugins. |
| `pluginWatchdogMaxErrors` | `3` | Default isolation threshold for one loaded plugin instance. |
| `allowPluginUnsafeGlobals` | `false` | Keeps raw UE4SS/native globals blocked in plugin environments. |
| `allowUnsafeApplicatorLuaHook` | `false` | Keeps the direct Lua applicator hook disabled. |
| `allowUnsafeMinigameConsoleCommands` | `false` | Default when absent; unsafe legacy minigame wrappers fail closed. |
| `allowUnsafeMinigameObjectSnapshot` | `false` | Keeps raw minigame UObject probes disabled. |
| `brickadiaSavedDir` | server `Saved` path when needed | Required for file-backed role/settings/player-log features; leave blank only when those features are not used. |

## Command Worker

| Environment variable | Safe value |
| --- | --- |
| `BMF_COMMAND_WORKER_POLL_MS` | `250` unless a canary proves otherwise |
| `BMF_COMMAND_WORKER_FALLBACK_POLL_MS` | `1000` unless a canary proves otherwise |
| `BMF_COMMAND_WORKER_MAX_FILES_PER_POLL` | `1` |
| `BMF_COMMAND_WORKER_ASYNC` | `1` when async loop support is available |
| `BMF_ALLOW_GAME_THREAD_LOOP` | unset or `0` unless validating fallback behavior |

## Socket Transport

Let the supported Omegga fork set `OMEGGA_BMF_SOCKET_*`. Do not hard-code socket
tokens in docs, examples, plugin config, or source control.

| Environment variable | Safe value |
| --- | --- |
| `OMEGGA_BMF_SOCKET_ENABLED` | managed by Omegga |
| `OMEGGA_BMF_SOCKET_HOST` | `127.0.0.1` |
| `OMEGGA_BMF_SOCKET_PORT` | assigned by Omegga |
| `OMEGGA_BMF_SOCKET_TOKEN` | generated by Omegga |
| `OMEGGA_BMF_SOCKET_POLL_MS` | `200` unless latency or frame-time evidence says otherwise |

## Runtime Brick State

Keep these disabled unless a targeted runtime-brick validation is active:

- `BMF_BRICK_RUNTIME_SET_ENABLED`
- `BMF_BRICK_RUNTIME_LOOKUP_ENABLED`
- `BMF_BRICK_VISIBILITY_SET_ENABLED`
- `BMF_BRICK_COLLISION_SET_ENABLED`
- `BMF_BRICK_RUNTIME_DIAGNOSTICS_ENABLED`
- `BMF_BRICK_CONTEXT_BACKGROUND_SCAN_ENABLED`

Runtime brick mutation also requires `L6 Frame Time` evidence before being
treated as a gameplay path.

## Omegga Adapters

| Setting | Safe value | Notes |
| --- | --- | --- |
| `OMEGGA_BMF_FORWARD_INTERACT` | unset or `false` | Forward Interactable events only when a BMF Lua handler is expected. |
| `allowUnsafeConsoleSnapshots` | `false` | Minigame adapters should prefer log/socket events over unsafe console snapshots. |
| `OMEGGA_BMF_COMMAND_DIR` | active `Mods/BMF/runtime/commands` | Prefer `OMEGGA_BMF_RUNTIME_DIR` when wiring several paths from one runtime root. |

## Native Samplers And Hooks

Enable `BMFFrameTelemetry` when collecting `L6 Frame Time` evidence. Disable the
sampler with `BMF_FRAME_TELEMETRY_ENABLED=0` when frame telemetry is not part of
the run.

Native hook refresh and injection remain maintainer workflows. Use
[Native Hook Notes](../maintainers/native-hooks.md) before changing them.
